The Industrial Challenge

Why Traditional Manufacturing Planning Breaks Down

High-mix, mission-critical electronics production (PCBA & Box-Build) operates under razor-thin tolerances. When unexpected part shortages occur, static ERP systems fail to evaluate holistic trade-offs.

4.1

Executive Summary

Manufacturing planners need to review production orders, material inventory, and deadlines to understand whether a material shortage may affect a production commitment. When these details are checked manually, the planner may need to compare multiple records and contact other teams before deciding what to do. If a shortage is found late, the team may have less time to evaluate options and could face schedule disruption or late delivery. The actual cost and frequency of these problems should be measured during a pilot.

The proposed Manufacturing Planning Agent helps the production planner identify material shortages and potential production delays. It receives production orders, inventory records, and deadlines, uses defined checking tools to compare the information, and can use the OpenAI API to help explain findings and prepare recommendations. The results are shown on a dashboard or as a response message. The agent recommends actions but does not independently make important production changes. The planner remains responsible for reviewing the evidence and approving the next step.

4.2

Solution Overview

Goal: Identify material shortages and potential production delays, then recommend possible next steps so the production planner can make an informed decision.
Scope: The proposed workflow starts when a user requests a check or enters new manufacturing data; reads production orders, inventory records, and deadlines; checks available quantities against requirements; flags shortages and deadlines at risk; uses the OpenAI API (when configured) to explain findings; displays findings on the dashboard; and requests human review.
Boundary Guardrail: The agent does not independently change production schedules, update inventory, place purchase orders, or approve substitute materials. Delivery-load optimization is outside the initial classroom scope and can be considered in advanced modules.
Main Users: Primary user is the Production Planner. Supported by inventory staff, production supervisors, purchasing, quality staff, and IT/security.
4.3

Agent Roster — Agent Card

FIELD SPECIFICATION
Name and Role Manufacturing Planning Agent – identifies material shortages and potential production delays.
Goal Find production problems and recommend solutions to help avoid delays.
Input / Trigger Triggered when a user requests a production check or enters new manufacturing data. Receives production orders, material inventory, and deadlines.
Tools and Data Sample production data, inventory records, deadlines, data-validation and shortage-checking functions, and an OpenAI API tool for analyzing findings and drafting recommendations.
Outputs Identified problems, shortage quantities, potential deadline risks, and recommendations displayed on the dashboard or in a response message.
Autonomy Level Level 2 Agentic AI – the agent analyzes data and proposes solutions, but requires human approval before important changes. It does not independently execute operational changes.
Failure Handling If data is missing, incomplete, inconsistent, or unclear, the system alerts the user and asks for corrected information. If the recommendation is uncertain, it labels uncertainty and asks the planner to verify. It must not make changes without approval.
4.4

Organization of the Agent

This design uses one main agent with specialized tools. The Manufacturing Planning Agent coordinates the workflow and uses tools for specific tasks rather than dividing the system into separate uncoordinated agents:

User request / new manufacturing data | v Manufacturing Planning Agent | +---------+----------+ | | | v v v Data checks Shortage Deadline-risk checker checker | | | +---------+----------+ | v OpenAI API recommendation (if configured; grounded in data) | v Dashboard / response message | v Human planner review approve / reject / revise | v No unapproved operational change
4.5

Step-by-Step Workflow & Sample Example

  1. The planner requests a production check or enters updated sample data.
  2. The agent validates that the required order, inventory, and deadline fields are present.
  3. The shortage-checking tool compares required material quantities with available inventory.
  4. The deadline-risk tool identifies orders affected by a shortage and displays the relevant deadline.
  5. The agent assembles findings and, if configured, asks OpenAI to explain the risk using only supplied facts.
  6. The dashboard displays the order, material, required quantity, available quantity, shortage, deadline, and recommendation.
  7. The planner reviews the information and approves, rejects, or revises the proposed next step.
  8. The prototype does not modify production schedules, inventory, or purchase orders without human sign-off.

Coursework Benchmark: Connector-X Shortage

A production order requires 120 units of Connector-X and the sample inventory shows 75 units. The shortage checker calculates a shortage of 45 units. The agent flags the order for review and recommends checking vendor replenishment timing, confirming whether an approved substitute is available, or assessing a schedule adjustment. The system strictly avoids claiming a substitute is suitable unless an authorized source confirms it.

4.9 Organizational Impact & Adoption

The agent reduces time spent gathering and comparing information, freeing planners to focus on exceptions. Change management requires framing the system as decision support, not an unassisted replacement for engineering judgment.

Adoption steps: user training on realistic shortages • gathering feedback on unhelpful advice • scaling only after reliable pilot metrics.
